# Как помочь проекту

Больше всего пользы приносят **реальные случаи с разных касс**: проект проверялся на одной конфигурации, и правила
могут давать ложные срабатывания или пропускать ошибки на других.

## Нашли ошибку или ложное срабатывание

Откройте Issue по шаблону и приложите **замаскированный** отчёт (кнопка «Собрать отчёт» на вкладке «Сводка», галочка
«Маскировать личные данные» включена). Перед отправкой просмотрите отчёт: названия организаций и адреса автоматически
не маскируются, добавьте их в `mask_extra` в `config.json`.

## Добавить или поправить правило разбора логов

Правила лежат в данных, не в коде: [`piothelper/rules.json`](piothelper/rules.json).

```json
{
  "key": "my_rule",
  "pattern": "регулярное выражение (без учёта регистра)",
  "level": "fail | warn | info",
  "title": "Короткое название проблемы",
  "advice": "Что делать",
  "transient": false
}
```

- Трёхзначные коды (514, 408…) не пишите голым числом: совпадут миллисекунды во времени `14:14:28.514`. Используйте
  `"codes": [{"n": "514", "extra": "нет ответа"}]` — код засчитывается только рядом со словами «код/error/ошибка» или
  словами из `extra`.
- `transient: true` — разовый сбой (связь, перезапуск): если давно не повторяется, показывается как «было, не повторяется».
- **Для каждого правила обязательны примеры** в [`tests/rule_cases.json`](tests/rule_cases.json): строки, которые оно
  находит, и (если нужно) общий набор строк-шумов, которые не должен находить ни один шаблон. Данные в примерах
  вымышленные: не копируйте реальные серийные номера, ИНН, ключи и коды маркировки.
- После правки увеличьте `rules_version` в начале файла (по нему работает кнопка «Обновить правила»).
- Если правило нужно только вам, положите его в `rules_user.json` рядом с программой (формат тот же; чтобы отключить
  встроенное правило: `{"key": "514", "disabled": true}`).

## Запуск тестов

```
python -m pip install -r requirements-dev.txt
python -m pytest
```

Тесты рассчитаны на Windows (используются службы, реестр и WinAPI). CI на GitHub запускает их на Python 3.10 и 3.12.

## Правила проекта

- Никаких реальных данных кассы в репозитории, тестах и Issues.
- Всё, что меняет систему (службы, сертификаты, файлы), выполняется только после подтверждения пользователя и пишется в `fixes.log`.
- Программа не вводит и не хранит токены, пароли и подписи.
